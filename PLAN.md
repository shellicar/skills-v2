# Plan

The order for adding skills back. Governed by `PHILOSOPHY.md`: nothing enters
unless it gives Claude enough context to do the task and the model wouldn't already
generalize it. Task skills are written the day a scenario needs one, not before.

## Done

**Always-on core** — communication, voice, audience, working-relationship,
teapot-protocol, co-working, testament, system-glossary.

**Actors** — operator.

## Now — finish the actors

Known standing need. Each expected to distill to a few lines, as `operator` did.

1. `supervisor` — check, don't ratify; weigh a verdict, don't inherit it; report honestly.
2. `handler` — works with the SC directly; holds project context; carries decisions up without taking them (leans on `audience-sc`).
3. `planner` — decides what work happens and in what order.

Listed for shape, not as a queue. Each stays unwritten until its scenario is live,
so its cost is zero until then.

- Platforms: `github`, `github-release`, `azure-devops`, `work-items`, `pr-review`
- Per-org: `conventions`
